# K5: match events for the announcer

> Owner: the announcer stream ([_agents/streams/archive/round3/announcer.md](../../../_agents/streams/archive/round3/announcer.md)). Proposed as C9;
> recorded as K5 in [_agents/workstreams.md](../../../_agents/workstreams.md). The announcer only **listens**: nothing
> here feeds back into the simulation.

A match is a **timeline**: a text file with one JSON object per line (`.jsonl`), ordered by tick. The fixtures in this
folder are generated by `tools/announcer/fake_match.py` (seeded) and checked by two validators that must agree:
`tools/announcer/events.py` (Python, `make announcer-validate`) and `game/announcer/announcer_events.gd` (GDScript, the
director's input check; `tests/announcer/test_announcer_events.gd`).

## Common fields

Every event has:

| Field | Type | Meaning |
|---|---|---|
| `tick` | int ≥ 0 | simulation tick (60 per second); never decreases along the file |
| `t` | number ≥ 0 | seconds since the match started; never decreases |
| `type` | string | one of the types below |

Unknown extra fields are allowed (the adapter may add more); unknown `type`s are errors.

## Naming

- **Teams:** `"green"` or `"rust"` (lowercase). The announcer says "Green" and "Rust".
- **Unit instances:** opaque ids, the `Match` tank name today (`"Green_Alpha_1"`). Fields that hold an instance id are
  `unit_id`, `shooter`, `victim`, `killer`, `target_id`.
- **Unit types:** `Units.PROFILES` ids (`scout`, `tank`, `ifv`, `artillery`, `lancer`, `burner`). Fields that hold a type
  end in `unit`: `unit`, `shooter_unit`, `victim_unit`, `killer_unit`, `target_unit`.
- **Never player names.** The announcer speaks of units by type and team color.
- **Ratios** (`hull`, `shield`, `hull_left`, `army_health`) are fractions of the maximum, `0.0`–`1.0`.

## Event types

| `type` | Required fields | Optional | Source in the game later |
|---|---|---|---|
| `match_start` | `arena` string, `budget` int, `teams` array of `{team, faction, units: [{id, unit}]}` (both teams) | `control_point` bool, per-team `army` name, per-unit `squad` | `Match` setup |
| `first_contact` | `team` (who fired first), `unit_id`, `unit`, `target_id`, `target_unit` | | the first shot fired |
| `damage` | `shooter`, `shooter_unit`, `victim`, `victim_unit`, `hull`, `shield`, `critical` bool | `amount` (hull fraction lost), `weak_spot` bool, `face` (`front`/`side`/`rear`) | K2 `projectile_impact` (rate-limited in the adapter) |
| `unit_destroyed` | `victim`, `victim_unit`, `victim_team`, `killer`, `killer_unit`, `killer_team`, `friendly` bool | `cause` (`weapon`/`hazard`); a hazard kill has empty `killer`, `killer_unit`, `killer_team` | `Match.tank_destroyed` |
| `friendly_fire` | `shooter`, `shooter_unit`, `victim`, `victim_unit`, `team`, `hull`, `killed` bool | | `Match.friendly_fire` |
| `close_call` | `unit_id`, `unit`, `team`, `hull_left` | | a unit still alive a few seconds after dropping below 15% hull |
| `control_changed` | `owner` (`green`/`rust`/`neutral`) | `previous` | `Match.control_changed` |
| `squad_wiped` | `team`, `squad` | `units_lost` int | the last unit of a squad destroyed |
| `momentum` | `army_health` `{green, rust}` | `units_left` `{green, rust}` | derived every 5 s |
| `match_end` | `winner` (`green`/`rust`/`draw`), `reason` (`elimination`/`control`/`time`), `duration_seconds`, `units_left` `{green, rust}`, `kills_by_unit` `{green: {unit: n}, rust: {unit: n}}` | | `Match.finished` (C3) |

**Timeline rules** (the validators check them): the first event is `match_start` and the last is `match_end`; exactly
one of each; ids referenced by later events exist in `match_start`; a destroyed unit is never destroyed again and never
shoots again; `first_contact` happens at most once.

**Kept small on purpose.** Streaks, comebacks, lead changes, first blood, "last unit standing", and callbacks are
*derived* by the director from these events; the game never has to compute them.

Deviations from the brief's first draft (2026-09-15, the announcer stream): instance and type fields got distinct names
(`unit_id` vs `unit`) so no field means two things; `friendly_fire` carries unit types and the team so a line can say
"Rust's own artillery"; `momentum` carries both teams in one event.

## Fixtures

| File | Scenario |
|---|---|
| `close_match.jsonl` | even armies, trades all match, decided in the last seconds |
| `blowout.jsonl` | one side outclasses the other quickly |
| `comeback.jsonl` | Rust leads by several units, Green claws back and wins |
| `friendly_fire_disaster.jsonl` | an artillery-heavy army shells its own front line |
| `scouts_vs_tanks.jsonl` | a scout swarm against a tank wall |
| `control_swing.jsonl` | the control point changes hands and decides the match |
| `gangs_vs_law.jsonl` | a road gang rushes the Law (factions are concept art this round; this exercises the faction lines) |
| `syndicate_showcase.jsonl` | the Syndicate's few expensive Lancers and artillery against a Condemned army |

A real match recorded by the booth (`make announcer-record-smoke` → `build/announcer/recorded.jsonl`) passes the same
validators; `game/announcer/match_event_adapter.gd` is the adapter from `Match` signals.

Regenerate with `make announcer-fixtures` (the same seeds give the same files).
