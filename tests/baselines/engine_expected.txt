# Engine messages that must NOT fail the test they land on, each with its reason.
#
# The test runner fails a test on any engine error or warning, and that rule is right: a message on a path a
# test drives is a defect in that path until someone says otherwise. `TestCase.expect_warning()` is how a
# test says otherwise about a message IT CAUSES. This file is for the other kind: messages a test cannot
# control and did not cause, which land on whichever test happens to be running.
#
# THE COST OF THIS FILE IS THAT IT IS A BLANKET EXEMPTION. Every line is one message nobody will be told
# about again, so:
#
#   * each line carries the REASON it is not a defect, in the comment above it, or it should not be here;
#   * a line that no longer occurs is REPORTED after every run, so the list is tightened rather than grown;
#   * matching is a substring, or a glob when the pattern contains `*` or `?`. An EMPTY line matches
#     nothing -- `contains("")` is true of every string, and a blanket exemption that reads like a specific
#     one is worse than no exemption at all;
#   * allowed messages are still COUNTED and printed ("N expected engine messages seen"), because an
#     exemption that is silent is indistinguishable from a run in which nothing happened.
#
# -- Jolt's job system saturating while the box is busy --
#
# `scenario_stride::test_the_half_rate_controller_still_dodges` failed on builder0 on 2026-09-20 with every
# one of its own assertions passing (ifv 8% vs 4%, tank 0% vs 3%, bar "no more than 10 points worse"). It
# failed only because this message landed on it, while five other streams were running.
#
# The message says of itself that it RECOVERS -- "Waiting for jobs to become available..." -- so it reports
# load, not a defect, and no test can control how busy the box is. It is a physics-engine thread-pool
# condition, not a game one.
#
# WHAT THE PROBE ESTABLISHED, and what it did not (`make remote T=error-type-probe`, builder0): the enum is
# error=0 warning=1 script=2 shader=3, `push_warning` arrives as 1, and this check is therefore correct for
# GDScript warnings. But the probe could NOT reproduce a C++-side warning, so why this message -- which
# Godot's own console prints as `WARNING:` -- reaches the runner as a non-warning is STILL OPEN. It is
# allowed here by its text, which is deliberately independent of that question; the runner now prints the
# numeric type with every engine error, so the next occurrence answers it rather than costing another probe.
